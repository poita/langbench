# scheme performance benchmark

Generated by `gen_bench.py` (fixed seeds); expected outputs come from `reference/main.py`
(about 30-40 s per input). All inputs are within SPEC.md: programs under 200 KB, recursion
depth at most 10,000, only the listed special forms and primitives. Run with
`python3 run_tests.py scheme --tests-dir problems/scheme/bench -- <impl>/run.sh`.

- `001_list_sort_records` — a 134 KB program, mostly a quoted dataset of 3,000 employee records
  that the interpreter must parse. It then merge-sorts and quicksorts 30,000 LCG integers, does
  repeated sorts with closure comparators, grouping with `filter`, tag counts, `equal?` string
  lookups and a `string-append` report. Measures reader throughput, allocation/GC of long
  lists, and calling closures and primitives in tight loops: ordinary list-processing Scheme.
- `002_call_intensive` — the core of the evaluator: naive `fib 27`, `tak 22 16 8`, Ackermann,
  9-queens, count-change, 1M-step mutual tail recursion via `letrec`, mutable closure counters,
  CPS closures, variadic `apply`, a meta-circular interpreter running fib 18, and 50 rounds of
  non-tail recursion 10,000 deep. Measures procedure call cost, environment lookup, closure
  creation and tail calls: the workloads named in the spec's Performance section, scaled up.
- `003_bignum_mixed` — arbitrary-precision arithmetic in realistic programs: a 1,500-digit
  pi spigot, `fact 5000` with digit sum, iterative `fib 40000`, Newton integer sqrt of 2·10^6000,
  big gcd, 521-bit Fermat `powmod`, Fermat-test prime search near 10^60, Collatz on 3^200+1,
  binomial(2000,1000), an exact harmonic number H(1000) and `display` output. Measures bignum
  multiply/divide/`number->string` mixed with ordinary interpretation.

## Long tier

`python3 bench/gen_bench.py --long` writes `bench-long/` with the same three programs, with their loop counts and
problem sizes raised (`LONG_SUBS` in `gen_bench.py`):

- 001 sorts 80,000 LCG integers, does 48 round-trips and 80 repeated record sorts.
- 002 runs `fib 32`, `tak 24 16 8`, `ack 3 7`, 10-queens, count-change 500, 5M-step mutual recursion, 200k counter
  rounds, 140k CPS loops, 5x the `apply` loops, meta-circular `fib 22` and 340 deep recursions.
- 003 computes 4,800 pi digits, `fact 16000`, `fib-iter 250000`, `isqrt` of 2·10^12000, Collatz on 3^400+1,
  binomial(4000,2000), a 240-row table and H(3500).

The programs stay within SPEC.md (no limit changed). Expected outputs come from `reference/main.py` (about 7 min for
all three).

Times are user CPU (single run at load average ~10-20 on 8 cores; an earlier, smaller version of this tier ran 35%
faster at load ~8 than under heavy load, so idle times will be somewhat lower):

| input | fastest (user s) | others (user s) | peak RSS compiled | python (wall / user, RSS) |
| --- | --- | --- | --- | --- |
| 001_list_sort_records | d 7.5 | cpp 8.2, rust 16.4, go 21.2 | 792 MB (rust) | 423 s / 274 s, 53 MB |
| 002_call_intensive | d 6.2 | cpp 7.2, go 9.0, rust 13.7 | 182 MB | 210 s / 188 s, 21 MB |
| 003_bignum_mixed | d 9.1 | rust 9.3, cpp 10.5, go 13.2 | 270 MB | 742 s / 697 s, 17 MB |

`bench-long/` is 164 KB. All five implementations pass all three. The Python implementation needs over 10 minutes on
003 (bignum-heavy).
